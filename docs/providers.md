# CAD provider contracts

The existing `IMechanicalCadProvider` defines the desktop CAD operations. `ICadWebProvider` is a sibling interface extending `ICadProvider`, not a replacement for the mechanical interface. It declares cloud-provider operations for authentication, document workspaces, elements, versions, exports, features, and assemblies.

`CadElementAddress` identifies a web CAD element by document ID, workspace or version ID, optional microversion ID, and element ID. Its JSON representation uses camel-case keys and omits a null microversion ID.

Onshape failures are represented by `CadProviderException` subclasses. `OnshapeApiException.FromHttpStatus` maps 401/403 to `OnshapeAuthException`, 409 to `OnshapeMicroversionSkewException`, and 429 to `OnshapeQuotaException` (including an optional retry interval). Other status codes produce `OnshapeApiException` with the status and reason.

The Core slice defines contracts and error types. The next client slice adds an unregistered HTTP request boundary with Basic API-key authorization, sorted query parameters, JSON request bodies, a write microversion-skew guard, and typed HTTP failures. The production client owns an HTTPS-only transport with automatic redirects disabled. Absolute request URLs must use the configured origin; other hosts or a scheme downgrade are rejected before credentials are sent. Redirect responses are returned only when explicitly requested, for callers to handle without forwarding credentials or a write body. Paths with an existing query retain it before the write guard; a conflicting guard in the path is rejected. Its focused tests use an in-memory HTTP handler; they do not make live CAD requests. Translation polling, quota retry, response JSON helpers, and the provider/manager/tool registrations belong to later slices. No server credential configuration or active-provider selection changes here.
